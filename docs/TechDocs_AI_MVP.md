# TechDocs AI — подробное описание MVP

## 1. Концепция продукта

**Рабочее название:** TechDocs AI

TechDocs AI — интеллектуальная база инженерной документации по объектам.

Приложение хранит:

- паспорта оборудования;
- руководства по эксплуатации;
- проектную документацию;
- рабочую документацию;
- исполнительную документацию;
- спецификации;
- схемы;
- акты;
- протоколы;
- регламенты технического обслуживания;
- инструкции;
- таблицы оборудования;
- другие технические файлы.

Пользователь выбирает объект и инженерную систему, задаёт вопрос обычным языком и получает ответ со ссылками на конкретные документы и страницы.

### Пример

**Вопрос:**

> Сколько дымовых пожарных извещателей установлено в школе №88?

**Ответ:**

> В документации найдено 214 дымовых пожарных извещателей:
>
> - ДИП-34А — 186 шт.;
> - ИП 212-141 — 28 шт.
>
> Источник: `Спецификация АПС.pdf`, страницы 27–29.

---

## 2. Главная цель MVP

MVP должен решить две основные задачи:

1. Быстро находить информацию в технической документации.
2. Хранить документацию в понятной структуре по объектам и инженерным системам.

Пользователь не должен каждый раз:

- искать файл вручную;
- скачивать его;
- загружать в отдельный ИИ-чат;
- заново объяснять контекст;
- повторно задавать объект и систему.

В первой версии приложение должно уметь:

- создавать объекты;
- добавлять инженерные системы;
- загружать документацию;
- автоматически обрабатывать документы;
- отвечать на вопросы по загруженной базе;
- показывать источник каждого ответа;
- находить информацию об оборудовании;
- подсчитывать оборудование по спецификациям;
- разделять поиск по объектам, системам и типам документов.

---

## 3. Что не включать в первую версию

Чтобы MVP не превратился в бесконечную разработку, сначала не нужны:

- полноценная мобильная версия;
- интеграция с Midio;
- автоматическое создание плановых работ;
- автоматическое формирование смет;
- сложное согласование документов;
- электронные подписи;
- интеграция с большим количеством облачных хранилищ;
- распознавание чертежей и условных обозначений на схемах;
- автоматический подсчёт оборудования непосредственно на планах;
- собственная обученная нейросеть;
- сложная ролевая модель для больших организаций;
- публичный SaaS с оплатой и тарифами.

Это можно добавить после проверки основной идеи.

## 4. Пользователи MVP

Для начала достаточно двух ролей.

### 4.1. Администратор

Может:

- создавать объекты;
- создавать разделы инженерных систем;
- загружать документы;
- удалять документы;
- изменять данные оборудования;
- запускать повторную обработку документов;
- видеть ошибки обработки;
- приглашать пользователей.

### 4.2. Пользователь

Может:

- просматривать доступные объекты;
- открывать документацию;
- задавать вопросы;
- использовать фильтры;
- просматривать карточки оборудования;
- переходить к источнику ответа.

Для первой локальной версии можно начать с одного пользователя без сложной системы регистрации.

## 7. Основные функции MVP

### 7.1. Создание объекта

Пользователь нажимает «Создать объект» и заполняет:

- название;
- адрес;
- описание;
- необходимые инженерные системы.

После создания открывается карточка объекта.

### 7.2. Загрузка документов

Пользователь выбирает:

```text
Объект: ЖК «Лето»
Система: АПС
Тип: Исполнительная документация
```

После этого загружает один или несколько файлов.

Поддерживаемые форматы первой версии:

- PDF;
- DOCX;
- XLSX;
- XLS;
- TXT;
- CSV;
- JPG;
- PNG.

Для каждого файла приложение должно показывать:

```text
Название
Размер
Статус загрузки
Статус обработки
Количество страниц
```

Можно добавить массовую загрузку папки.

### 7.3. Автоматическая обработка документов

После загрузки система:

1. Сохраняет оригинальный файл.
2. Определяет формат.
3. Извлекает текст.
4. Определяет страницы.
5. Извлекает таблицы.
6. Делит текст на небольшие фрагменты.
7. Создаёт векторные представления фрагментов.
8. Сохраняет их в поисковой базе.
9. Пытается определить производителя, модели и оборудование.
10. Помечает документ как готовый.

Если PDF представляет собой скан, система запускает OCR.

Для MVP можно предусмотреть ограничение:

```text
Максимальный размер файла: 100 МБ
Максимальное количество страниц: 500
```

## 8. Чат с документацией

Главный экран приложения — чат.

Перед вопросом пользователь может выбрать область поиска:

```text
Объект: ЖК «Лето»
Система: АПС
Тип документа: Все
Оборудование: Все
```

После этого вводит:

> Какое назначение прибора С2000-ПП?

Система выполняет поиск только в выбранной области.

Ответ должен выглядеть так:

> С2000-ПП предназначен для передачи извещений между приборами системы «Орион» и внешними системами по интерфейсу Modbus.
>
> **Источники:**
>
> 1. `С2000-ПП Руководство.pdf`, стр. 5.
> 2. `Инструкция по интеграции АПС.pdf`, стр. 18.

Под ответом:

- кнопка «Открыть источник»;
- кнопка «Скопировать»;
- кнопка «Ответ неверный»;
- кнопка «Полезный ответ».

## 9. Правила работы ИИ

ИИ не должен отвечать только на основании общих знаний, если пользователь выбрал поиск по базе.

Правильный алгоритм:

1. Определить смысл вопроса.
2. Определить объект и систему.
3. Найти подходящие фрагменты документов.
4. Проверить, достаточно ли информации.
5. Сформировать ответ.
6. Приложить источники.
7. Сообщить об отсутствии информации, если её нет.

Пример правильного ответа:

> В загруженной документации периодичность технического обслуживания не указана. Найден только порядок проверки работоспособности.

Пример неправильного ответа:

> Рекомендуется проводить ТО раз в год.

Если в документах этого нет, ИИ не должен придумывать периодичность.

## 10. Режимы поиска

### 10.1. По текущему объекту

Вопрос обрабатывается только по выбранному объекту.

Пример:

> Какие модели контроллеров СКУД используются на этом объекте?

### 10.2. По всем объектам

Пример:

> На каких объектах используется Термотроник ТВ7?

Ответ:

```text
1. ЖК «Лето» — 2 прибора
2. Поликлиника №11 — 1 прибор
3. Ледовый дворец — 1 прибор
```

### 10.3. По конкретному документу

Пользователь открывает паспорт и спрашивает:

> Какие регистры отвечают за температуру подачи?

---

## 11. Подсчёт оборудования

Это отдельная важная функция.

Обычный RAG-поиск не гарантирует правильный подсчёт, поэтому количественные запросы нужно обрабатывать отдельно.

### 11.1. Как должно работать

После загрузки спецификации система пытается извлечь таблицу:

| Производитель | Наименование | Модель | Количество |
|---|---|---|---:|
| Болид | Извещатель дымовой | ДИП-34А | 186 |
| Рубеж | Извещатель ручной | ИПР 513-11 | 24 |

Данные сохраняются в таблицу оборудования.

Пользователь может проверить и исправить их.

После подтверждения запрос:

> Сколько дымовых извещателей на объекте?

обрабатывается не по случайным фрагментам PDF, а по базе оборудования.

### 11.2. Результат подсчёта

```text
Дымовые пожарные извещатели — 214 шт.

ДИП-34А — 186 шт.
ИП 212-141 — 28 шт.
```

Источники:

```text
Спецификация АПС.pdf, стр. 27
Исполнительная спецификация.pdf, стр. 11
```

Если найдены две похожие спецификации, приложение должно предупредить:

> Найдены проектная и исполнительная спецификации. Количество отличается. Для ответа использована исполнительная документация как более актуальная.

## 16. Интеграция с Google Drive

Интеграцию лучше сделать после стабильной ручной загрузки, но архитектуру заложить сразу.

### Вариант работы

Для объекта указывается папка:

```text
Google Drive/Объекты/ЖК Лето
```

Подпапки:

```text
АПС
СКУД
Вентиляция
ИТП
```

Приложение периодически проверяет папку.

Для каждого файла сохраняются:

```text
Google Drive File ID
Дата изменения
Контрольная сумма
Путь
Статус синхронизации
```

При синхронизации:

- новый файл загружается;
- изменённый файл переобрабатывается;
- удалённый файл помечается как удалённый;
- неизменившийся файл повторно не обрабатывается.

В MVP интеграция может быть ручной:

> Синхронизировать сейчас.

## 17. Работа с версиями

У одного документа могут быть разные версии.

Пример:

```text
Проект АПС от 2024 года
Исполнительная документация от 2025 года
Скорректированная спецификация от 2026 года
```

В приложении должна быть возможность:

- отметить документ актуальным;
- указать, какой документ заменяет предыдущий;
- хранить историю;
- исключать устаревшие документы из ответов.

По умолчанию ИИ ищет только по актуальным документам.

---

## 18. Поиск дубликатов оборудования

Система должна находить похожие записи:

```text
ДИП-34А
ДИП 34А
ДИП34-А
Болид ДИП-34А
ДИП-34 А
```

Она предлагает пользователю:

> Возможно, это одна модель оборудования. Объединить записи?

Пользователь выбирает:

```text
Объединить
Оставить отдельно
Решить позже
```

Автоматически объединять спорные модели не нужно.

## 20. Требования к ответам ИИ

Каждый ответ должен содержать:

1. Краткий ответ.
2. Подробное объяснение.
3. Название источника.
4. Номер страницы или листа.
5. Цитируемый фрагмент.
6. Уровень уверенности.

Пример:

```text
Ответ:
Техническое обслуживание включает внешний осмотр,
удаление пыли и проверку работоспособности.

Источник:
Руководство ДИП-34А.pdf, стр. 18, раздел 3.3.

Уверенность:
Высокая.
```

Если источники противоречат друг другу:

```text
В проектной документации указано 186 устройств,
а в исполнительной документации — 192 устройства.

Необходимо уточнить, какой документ считать актуальным.
```

## 25. Логика RAG

### Этап загрузки

```text
Документ
→ извлечение текста
→ разделение по страницам
→ разделение на фрагменты
→ создание embeddings
→ сохранение в pgvector
```

### Этап вопроса

```text
Вопрос пользователя
→ определение фильтров
→ поиск релевантных фрагментов
→ проверка источников
→ формирование контекста
→ отправка в языковую модель
→ ответ со ссылками
```

### Размер фрагментов

Начальные настройки:

```text
Размер: 500–1 000 токенов
Перекрытие: 100–150 токенов
```

Для таблиц лучше сохранять:

- таблицу целиком;
- отдельные строки;
- заголовки колонок вместе с каждой строкой.

## 26. Отдельная обработка вопросов о количестве

При получении вопроса:

> Сколько пожарных извещателей?

Система определяет, что это количественный запрос.

После этого:

1. Ищет данные в таблице оборудования.
2. Фильтрует по объекту и системе.
3. Группирует модели.
4. Суммирует подтверждённые количества.
5. Показывает формулу расчёта.
6. Прикладывает источники.

Пример внутреннего результата:

```json
{
  "category": "пожарный дымовой извещатель",
  "items": [
    {
      "model": "ДИП-34А",
      "quantity": 186
    },
    {
      "model": "ИП 212-141",
      "quantity": 28
    }
  ],
  "total": 214
}
```

## 27. Обработка ошибок

Пользователь должен видеть понятное сообщение.

Не так:

```text
NullPointerException
```

А так:

```text
Не удалось извлечь текст из документа.
Возможно, PDF состоит из изображений.
Попробуйте запустить OCR.
```

Возможные ошибки:

- файл повреждён;
- формат не поддерживается;
- документ защищён паролем;
- OCR не смог распознать текст;
- ИИ-провайдер недоступен;
- слишком большой файл;
- таблица не распознана;
- отсутствует связь с Google Drive.

## 28. Безопасность

Минимальные требования:

- документы разных организаций не должны смешиваться;
- доступ к файлам только после авторизации;
- пароли хранятся только в виде хеша;
- все действия с удалением логируются;
- оригиналы документов не изменяются;
- резервное копирование базы и файлов;
- API-ключ ИИ хранится в переменных окружения;
- возможность полностью удалить объект и его данные.

Для закрытых объектов полезно предусмотреть локальное развёртывание без передачи документов во внешние сервисы.

## 32. Критерии готовности MVP

MVP можно считать готовым, если выполняются следующие сценарии.

### Сценарий 1

Пользователь создаёт объект «ЖК Лето», добавляет систему АПС и загружает паспорт.

После обработки он спрашивает:

> Какое назначение прибора?

Система отвечает и указывает страницу.

### Сценарий 2

Пользователь загружает спецификацию XLSX.

Приложение создаёт записи оборудования с моделями и количеством.

### Сценарий 3

Пользователь спрашивает:

> Сколько дымовых извещателей на объекте?

Система выводит модели, количество, сумму и источники.

### Сценарий 4

Пользователь выбирает все объекты и спрашивает:

> Где установлен ТВ7?

Приложение показывает список объектов.

### Сценарий 5

Если информации нет, система отвечает:

> В загруженных документах ответ не найден.

Она не выдумывает данные.

### Сценарий 6

Пользователь нажимает на источник и видит нужный файл и страницу.
